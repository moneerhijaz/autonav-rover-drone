# Teensy micro-ROS Rover Notes - 2026-07-09

Short record of what was set up today for driving the tracked rover from ROS 2 Jazzy through a Teensy 4.1 and the Hiwonder 4-channel encoder motor driver.

## Hardware

- PC/robot machine runs ROS 2 Jazzy.
- Teensy 4.1 runs PlatformIO Arduino firmware.
- Hiwonder 4-channel encoder motor driver is on I2C address `0x34`.
- Teensy I2C pins:
  - SDA: pin `18`
  - SCL: pin `19`
- Chassis motors are Hiwonder JGB encoder gear motors.
- Motor driver outputs in use:
  - `M1`: one track
  - `M3`: other track
  - `M2` and `M4`: unused, commanded `0`

## Firmware Layout

Main firmware:

```text
firmware/teensy_motor_controller/src/main.cpp
```

I2C scanner:

```text
firmware/teensy_motor_controller/src/i2c_scanner.cpp
```

PlatformIO uses two envs:

```text
teensy41           -> builds main micro-ROS motor firmware
teensy41_i2c_scan  -> builds only the I2C scanner
```

The scanner found:

```text
Found I2C device at 0x34
```

## PlatformIO Config

Important settings in `firmware/teensy_motor_controller/platformio.ini`:

```ini
[env:teensy41]
platform = teensy
board = teensy41
framework = arduino
monitor_speed = 115200
upload_protocol = teensy-cli
build_src_filter =
    +<main.cpp>
    -<i2c_scanner.cpp>
extra_scripts =
    pre:scripts/microros_build_flags.py

board_microros_transport = serial
board_microros_distro = jazzy

lib_deps = https://github.com/micro-ROS/micro_ros_platformio
```

The build flag helper is:

```text
firmware/teensy_motor_controller/scripts/microros_build_flags.py
```

It adds the small compiler flags needed for this Teensy/micro-ROS PlatformIO build.

## micro-ROS Agent Setup

One way to reproduce the agent install from source:

```bash
mkdir -p ~/microros_ws/src
cd ~/microros_ws/src
git clone -b jazzy https://github.com/micro-ROS/micro_ros_setup.git

cd ~/microros_ws
source /opt/ros/jazzy/setup.bash
rosdep update
rosdep install --from-paths src --ignore-src -y
colcon build
source install/setup.bash

ros2 run micro_ros_setup create_agent_ws.sh
ros2 run micro_ros_setup build_agent.sh
source install/setup.bash
```

Run the agent:

```bash
source /opt/ros/jazzy/setup.bash
source ~/microros_ws/install/setup.bash
ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyACM0 -v6
```

Better stable device path once the Teensy serial device exists:

```bash
ros2 run micro_ros_agent micro_ros_agent serial \
  --dev /dev/serial/by-id/usb-Teensyduino_USB_Serial_19918170-if00 \
  -v6
```

Do not run `platformio device monitor` and `micro_ros_agent` on the same serial port at the same time.

## Firmware Build And Upload

Build main firmware:

```bash
cd ~/Projects/autonav-rover-drone/firmware/teensy_motor_controller
pio run --environment teensy41
```

Upload main firmware:

```bash
pio run --environment teensy41 --target upload
```

Build/upload scanner if needed:

```bash
pio run --environment teensy41_i2c_scan
pio run --environment teensy41_i2c_scan --target upload
pio device monitor --environment teensy41_i2c_scan --port /dev/ttyACM0
```

Important Teensy note: the onboard button is Program, not reset. Pressing it can put the Teensy into Halfkay bootloader mode, where the normal serial device disappears. If that happens, upload firmware again or unplug/replug USB.

## Firmware micro-ROS Pieces

Required includes:

```cpp
#include <micro_ros_platformio.h>
#include <rcl/rcl.h>
#include <rclc/rclc.h>
#include <rclc/executor.h>
#include <std_msgs/msg/int32.h>
#include <geometry_msgs/msg/twist.h>
```

Required serial transport setup:

```cpp
Serial.begin(115200);
set_microros_serial_transports(Serial);
```

Core ROS setup used in `main.cpp`:

```cpp
rclc_support_init(&support, 0, NULL, &allocator);
rclc_node_init_default(&node, "teensy_base", "", &support);

rclc_subscription_init_default(
  &cmd_vel_subscriber,
  &node,
  ROSIDL_GET_MSG_TYPE_SUPPORT(geometry_msgs, msg, Twist),
  "cmd_vel"
);

rclc_publisher_init_default(
  &publisher,
  &node,
  ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32),
  "teensy/heartbeat"
);

rclc_executor_init(&executor, &support.context, 2, &allocator);
rclc_executor_add_subscription(
  &executor,
  &cmd_vel_subscriber,
  &cmd_vel_msg,
  &cmd_vel_callback,
  ON_NEW_DATA
);
```

The loop must keep spinning the executor:

```cpp
rclc_executor_spin_some(&executor, RCL_MS_TO_NS(100));
```

## Motor Driver Settings

Current important constants:

```cpp
constexpr uint8_t MOTOR_I2C_ADDR = 0x34;
constexpr uint8_t MOTOR_TYPE = MOTOR_TYPE_JGB;
constexpr uint8_t MOTOR_FIXED_SPEED_ADDR = 0x33;

constexpr float LINEAR_TO_MOTOR_SPEED = 100.0f;
constexpr float ANGULAR_TO_MOTOR_SPEED = 100.0f;
constexpr int8_t MAX_MOTOR_SPEED = 100;
constexpr uint32_t CMD_VEL_TIMEOUT_MS = 500;

constexpr int8_t M1_FORWARD_SIGN = -1;
constexpr int8_t M3_FORWARD_SIGN = 1;
```

Command mapping:

```text
linear.x = 1.0  -> 100 percent forward command
linear.x = 0.5  -> 50 percent forward command
angular.z = 1.0 -> 100 percent turn command
```

Firmware writes:

```text
M1 = left/right track speed
M2 = 0
M3 = opposite track speed
M4 = 0
```

Continuous forward:

## Keyboard Control

Install:

```bash
sudo apt install ros-jazzy-teleop-twist-keyboard
```

Run over SSH:

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -r cmd_vel:=/cmd_vel \
  -p speed:=0.25 \
  -p turn:=0.50 \
  -p repeat_rate:=30.0 \
  -p key_timeout:=0.10
```

Useful keys:

```text
i = forward
, = backward
j = rotate left
l = rotate right
k = stop
q/z = increase/decrease both speed and turn
w/x = increase/decrease linear speed only
e/c = increase/decrease angular speed only
Ctrl+C = quit
```

If `turn` shows `0.00`, restart teleop with `-p turn:=0.50`. Multiplying zero by the keyboard shortcuts can keep it at zero.

## Notes From Debugging

- Seeing binary `XRCE` text in PlatformIO monitor is normal micro-ROS serial traffic.
- If only `/parameter_events` and `/rosout` show, the Teensy has not connected to the agent yet.
- Rebuilding/uploading the firmware fixed a case where `/teensy_base` did not appear.
- `CMD_VEL_TIMEOUT_MS = 150` felt too twitchy over WiFi/SSH and caused slow/hesitant starts.
- `CMD_VEL_TIMEOUT_MS = 500` made startup motion smooth again.
- `key_timeout:=0.10` is still useful because teleop sends stop quickly when the key is released.
