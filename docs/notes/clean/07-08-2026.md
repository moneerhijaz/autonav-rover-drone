## Inspecting Running Nodes

### Step-by-Step

1. List the currently running ROS 2 nodes.
2. Pick a node name from the list.
3. Use `ros2 node info` to inspect that node.

### Command

```bash
ros2 node list
```

### Explanation

Lists all currently running ROS 2 nodes.

* `ros2`: ROS 2 command-line tool
* `node`: works with ROS 2 nodes
* `list`: shows active nodes

---

### Command

```bash
ros2 node info /<node_name>
```

### Explanation

Shows detailed information about a running node.

* `node`: works with ROS 2 nodes
* `info`: displays details about one node
* `/<node_name>`: name of the node to inspect

Example:

```bash
ros2 node info /teleop_turtle
```

### Explanation

Shows information about the `/teleop_turtle` node, including:

* Subscribers
* Publishers
* Service servers
* Service clients
* Action servers
* Action clients

## Inspecting Topics

### Step-by-Step

1. List active topics.
2. View topic types.
3. Echo topic data.
4. Inspect topic publisher/subscriber information.

### Command

```bash
ros2 topic list
```

### Explanation

Lists all active ROS 2 topics.

* `topic`: works with ROS 2 topics
* `list`: shows active topics

---

### Command

```bash
ros2 topic list -t
```

### Explanation

Lists active ROS 2 topics and their message types.

* `-t`: shows the type of each topic

---

### Command

```bash
ros2 topic echo <topic_name>
```

### Explanation

Prints live messages being published on a topic.

* `echo`: displays topic messages in the terminal
* `<topic_name>`: topic to listen to

Example:

```bash
ros2 topic echo /turtle1/cmd_vel
```

### Explanation

Prints velocity command messages published on `/turtle1/cmd_vel`.

---

### Command

```bash
ros2 topic info <topic_name>
```

### Explanation

Shows information about a topic.

* `info`: displays topic details
* `<topic_name>`: topic to inspect

This can show details such as:

* Message type
* Number of publishers
* Number of subscribers

## Inspecting Interfaces

### Step-by-Step

1. Find the message, service, or action type.
2. Use `ros2 interface show` to inspect its structure.

### Command

```bash
ros2 interface show <interface_type>
```

### Explanation

Shows the fields inside a message, service, or action interface.

* `interface`: works with ROS 2 interfaces
* `show`: displays the structure of an interface
* `<interface_type>`: message, service, or action type to inspect

Example:

```bash
ros2 interface show geometry_msgs/msg/Twist
```

### Explanation

Shows the fields inside the `Twist` message type.

## Inspecting Parameters

### Step-by-Step

1. List parameters on a node.
2. Read a parameter value.
3. Change a parameter value.
4. Save parameters to a file if needed.

### Command

```bash
ros2 param list /<node_name>
```

### Explanation

Lists parameters available on a node.

* `param`: works with ROS 2 parameters
* `list`: shows available parameters
* `/<node_name>`: node to inspect

Example:

```bash
ros2 param list /teleop_turtle
```

### Explanation

Lists parameters for the `/teleop_turtle` node.

---

### Command

```bash
ros2 param get /<node_name> <param_name>
```

### Explanation

Gets the current value of a parameter.

* `get`: reads a parameter value
* `/<node_name>`: node that owns the parameter
* `<param_name>`: parameter to read

---

### Command

```bash
ros2 param set /<node_name> <param_name> <value>
```

### Explanation

Sets a new value for a parameter.

* `set`: changes a parameter value
* `/<node_name>`: node that owns the parameter
* `<param_name>`: parameter to change
* `<value>`: new value to assign

---

### Command

```bash
ros2 param dump /<node_name>
```

### Explanation

Prints all parameters from a node.

* `dump`: outputs parameters in YAML format
* `/<node_name>`: node to dump parameters from

---

### Command

```bash
ros2 param dump /<node_name> > params.yaml
```

### Explanation

Saves a node’s parameters to a YAML file.

* `dump`: outputs parameters
* `>`: redirects terminal output into a file
* `params.yaml`: file where the parameters are saved

## Building ROS 2 Workspaces

### Step-by-Step

1. Build the workspace with `colcon`.
2. Source the workspace setup file.
3. Run or test packages from the workspace.

### Command

```bash
colcon build --symlink-install
```

### Explanation

Builds the ROS 2 workspace using symbolic links.

* `colcon`: build tool used by ROS 2
* `build`: builds the workspace
* `--symlink-install`: links files instead of copying them, useful during development

---

### Command

```bash
colcon build --packages-select <package_name>
```

### Explanation

Builds only one selected package.

* `--packages-select`: builds only the listed package
* `<package_name>`: package to build

---

### Command

```bash
source install/local_setup.bash
```

### Explanation

Sources the workspace so ROS 2 can find the built packages.

* `source`: runs setup commands in the current terminal
* `install/local_setup.bash`: setup file generated after building the workspace

---

## Creating ROS 2 Packages

### Step-by-Step

1. Go into the workspace `src` folder.
2. Create a new package.
3. Build the workspace.
4. Source the setup file.

### Command

```bash
ros2 pkg create --build-type ament_cmake --node-name <node_name> <package_name>
```

### Explanation

Creates a new ROS 2 package with a starter node.

* `pkg create`: creates a new ROS 2 package
* `--build-type ament_cmake`: uses the CMake-based ROS 2 build system
* `--node-name <node_name>`: creates a starter node with this name
* `<package_name>`: name of the new package

---

## Installing Dependencies

### Step-by-Step

1. Go to the root of the ROS 2 workspace.
2. Run `rosdep` to install missing dependencies.
3. Build the workspace again.

### Command

```bash
rosdep install -i --from-path src --rosdistro humble -y
```

### Explanation

Installs missing dependencies for packages inside the `src` folder.

* `rosdep`: installs ROS package dependencies
* `install`: installs required dependencies
* `-i`: ignores packages that are already installed
* `--from-path src`: checks packages inside the `src` directory
* `--rosdistro humble`: uses dependency rules for ROS 2 Humble
* `-y`: automatically confirms installation prompts
